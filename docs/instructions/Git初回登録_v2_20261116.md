## 1. 機密チェック（前版 §4 を置き換える）

### 1.1 検索する語

- 検索する語を、ファイルに直接書かないこと。実行時に、次のコマンドで取得する。
  - 利用者名：`$env:USERNAME`
  - 社名：`git config user.email` の `@` より後ろの、最初の区切り（例：`xxx.co.jp` の `xxx`）
- 検索する対象は、次の4つとする。
  - 利用者名
  - `C:\Users\`
  - 社名
  - メールアドレスの形
- 検索する範囲は、追跡の対象になる全ファイルとする（.gitignore を適用した後）。

### 1.2 結果の扱い

| 該当した場所 | 扱い |
|---|---|
| `licenses/` 配下、`THIRD_PARTY_NOTICES.md` に書かれた、第三者のメールアドレスや著作権表示 | **許可する。** ライセンス原文は改変しない。ただし、利用者名と社名が含まれていないことは確認する |
| `docs/` 配下にある、`C:\Users\<利用者名>\...\schedule-roadmap-builder\...` の形の絶対パス | プロジェクト直下からの相対パスに書き換える（例：`publish\ScheduleRoadmapBuilder.App.exe`） |
| `docs/` 配下にある、その他の `C:\Users\<利用者名>` | `%USERPROFILE%` に書き換える |
| `docs/instructions/Git初回登録_20261116.md` の96〜101行目付近にある、検索する語の記載 | 検索する語の部分を、`<利用者名>`、`<社名>` などの汎用の表記に書き換える。その行の他の部分は変えない |
| 上記以外の場所で、利用者名・社名・利用者本人のメールアドレスが見つかった場合 | 停止して報告する |

### 1.3 書き換えた後の確認

- 書き換えた後に、§1.1 の検索をもう一度行う。
- 結果が「許可する」に当たるものだけになっていることを確認する。
- 書き換えた箇所は、すべて一覧にして報告する（ファイル・行・書き換える前と後）。
- 報告では、利用者名と社名を `<利用者名>`、`<社名>` と書く。

## 2. 停止条件（前版 §1 を置き換える）

1. `.git` がすでにある。
2. `git config user.name` または `git config user.email` が設定されていない。
3. §1.2 の「停止して報告する」に当たるものが見つかった。
4. push がリモートに拒否された。
5. 認証のエラーが出た。
