# 指示：schedule-roadmap-builder をgitで管理し、GitHubに初回pushする

## 0. 前提

- ツールは完成済みで、利用者の確認も済んでいる。**コードの動作は一切変えない。**
- リモート：`https://github.com/h-imabeppu/schedule-roadmap-builder.git`
- ブランチ：`main`のみを使う。
- 今回の作業に限り、git init / add / commit / push を許可する。
  - これらの操作で承認を求められた場合は、利用者が手動で承認する。
  - force push、履歴の書き換え、リモートの設定変更（URL以外）は禁止する。
- ファイルの削除は禁止する。

## 1. 停止条件（停止して、理由・事実・推奨案を報告する）

1. すでに `.git` がある。
2. `git config user.name` または `git config user.email` が未設定である。
   - 推測で設定しないこと。
3. §4 の機密チェックで、絶対パス以外に該当が見つかった。
4. pushがリモートに拒否された（リモートに既にコミットがある場合など）。
   - pull・merge・force push はしないこと。
5. push時に認証のエラーが出た。

## 2. .gitignore の作成（ルート）

最低限、次のファイルとフォルダを除外する。

```
# ビルド成果物
bin/
obj/
publish/
TestResults/
# Visual Studio / VS Code
.vs/
*.user
*.suo
# このプロジェクト専用のNuGet保存先（Directory.Build.props で指定している場合）
.nuget-packages/
# 一時ファイル・バックアップ
_tmp_*
*.bak
*.log
# テストで再生成するサンプル出力
samples/output/
```

- `Directory.Build.props` の `RestorePackagesPath` を確認し、上記と違うパスの場合は、そのパスを除外する。
- 次のファイルとフォルダは、除外しないこと。
  - `licenses/`
  - `THIRD_PARTY_NOTICES.md`
  - `samples/sample.srb.json`
  - `docs/`
  - `.github/`
  - `tools/`

## 4. 機密チェック（commitの前に必ず実施する）

1. 追跡の対象になるファイル（.gitignore を適用した後のファイル）を、次のパターンで検索する（大文字と小文字は区別しない）。
   - `<利用者名>`
   - `C:\Users\`
   - `<社名>`
   - `@` を含むメールアドレスの形
2. 結果の扱い
   - 該当が、`docs/` 内の絶対パス（`C:\Users\...\schedule-roadmap-builder\...`）だけの場合：プロジェクト直下からの相対パスに書き換えてよい。書き換えた箇所は、すべて報告する。
   - それ以外に該当がある場合：停止条件3として停止し、該当したファイル・行・内容を報告する。
3. サンプルとテストのデータが架空のデータであることを確認する。
   - 担当者名は A／B／C などの仮の名前であること。

## 6. 最終確認とcommit・push

1. `dotnet build -warnaserror` と `dotnet test` を実行し、成功することを確認する。
   - 件数を記録する。
2. 次のコマンドで、リポジトリを作成してステージする。
   ```
   git init -b main
   git add .
   git status --porcelain
   ```
3. ステージに、次のファイルとフォルダが含まれていないことを確認する。
   - `bin/`、`obj/`、`publish/`、`_tmp_*`、`*.bak`、`.nuget-packages/`
   - 含まれている場合は、.gitignore を直してやり直す。
4. 次のコマンドでcommitする。
   ```
   git commit -m "初版: schedule-roadmap-builder（仕様v0.4c）"
   ```
5. 次のコマンドでpushする。
   ```
   git remote add origin https://github.com/h-imabeppu/schedule-roadmap-builder.git
   git push -u origin main
   ```
6. 次のコマンドで、結果を確認する。
   ```
   git log --oneline -1
   git show --stat HEAD
   git status
   ```
