# 指示：schedule-roadmap-builder 改修（仕様v0.4の反映）

## 0. この指示の位置付け

- 正本は `docs/specification.md`（v0.4b）である。仕様書の中で「v0.4」と記した箇所が、今回の改修対象である。
- 初版は完成済みで、動作確認も済んでいる。経緯は `docs/progress.md` を参照する。
- 本指示の範囲では、仕様の範囲内であれば、実装の詳細を自分で判断して進めてよい。
- 利用者は、途中で承認したり回答したりしない。止まらずに、最後までやり切ること。
- 判断した内容は、`docs/progress.md` の「実装時の判断メモ」に記録する。

## 1. 停止条件（次の2つだけ）

1. NuGetの復元が失敗する。
   - まず `--disable-parallel` を付けて再実行する。それでも失敗する場合は、プロジェクトを1つずつ復元する。
   - それでも成功しない場合に限り、停止する。
2. §2.1にも推移的依存にも当たらないパッケージが、新たに必要になった。
   - Excel出力は、既存の DocumentFormat.OpenXml で実装する。

上記以外は止まらない。

同じ問題を5回直しても解消しない場合は、次の方法で先へ進める。
- 該当するテストに `Skip`（理由付き）を付ける。
- または、該当する機能を最小限の実装にとどめる。
- どちらの場合も、判断メモに記録する。

## 2. 禁止事項

- git の操作
- ファイルの削除（不要なファイルは、`_tmp_` という接頭辞を付けた名前に変える）
- 共有のNuGetキャッシュの削除やクリア
- §12にある対象外の機能の実装
- 実際の案件名や人名の使用
- MCPの使用

## 3. 作業内容

各段階で `dotnet build -warnaserror` と `dotnet test` が成功してから、次の段階へ進む。

### 段階1：画面（§5.2、§7.2、§7.5、§8、§11）

**入力の即時反映**
- コンボボックスの列は、値を選んだ時点で確定させる。
- 実装の例：`CurrentCellDirtyStateChanged` で `CommitEdit` を呼ぶ。

**今日の1本線**
- セルごとの赤枠をやめる。
- 全行を貫く1本の縦線にする。
- 実装の例：今日の列の中央に、各セルで同じx座標の縦線を描く。上下の境目でも線がつながるようにする。

**ホイール操作**
- Shift＋ホイールで、横にスクロールする。
- Ctrl＋ホイールで、ズームする。
- 次のキー操作もズームに使う：Ctrl＋0、Ctrl＋＋、Ctrl＋−。

**ズーム**
- 倍率の計算は、Coreに置く（`ZoomLevel` などの名前で、テストを付ける）。
- 倍率を変えるときは、`SuspendLayout` などを使って、まとめて再描画する。
- ステータスバーに、現在の倍率を表示する。

**設定画面の色見本**
- 担当者の一覧で、色のコードの横に、その色で塗った見本を表示する。

### 段階2：PPT（§10.2、§10.4）

- 月・CW・日のヘッダ、大項目名の列、網掛け、グリッド線を、PowerPointの表1つにまとめる（v0.4b）。
  - 網掛けやグリッド線を個別の図形で作っている既存の処理は、表に置き換える。
  - 網掛けはセルの塗りつぶし、グリッド線はセルの罫線で表す。罫線は、セルごとに設定する（a:lnL / a:lnR / a:lnT / a:lnB）。
  - 月とCWの段はセルを結合する（gridSpan / hMerge）。
- 矢印、◆と名称、今日の線は、表の上に置く個別の図形とする。位置は、表の列の位置から計算する。
- マイルストーン：◆に白い縁取りを付け、名称は◆の右側に隣接して置く。
- 重なりの順序は、背面から次の順にする：表 → 矢印 → ◆と名称 → 今日の線。
- 3か月・全日付のサンプルでは、表が75列を超える。OpenXmlValidatorでエラーが0件であることを確認する。PowerPointで開けるかどうかは、人が確認する。

### 段階3：Excel出力（§9.5、§11）

- `ExcelExporter` をCoreに作成する。
- メニューに「Excel出力」を追加する。出力範囲は「全項目」と「大項目とマイルストーンのみ」から選べるようにする。
- セルの書式と塗りつぶしは、StylesheetのFillを、担当者の色ごとに作成して実装する。

### 段階4：テスト（§13.1「v0.4で追加するテスト」）と、サンプルの出力の更新

- 次のファイルを、サンプルから再生成するテストを用意する。
  - `samples/output/sample.png`
  - `samples/output/sample-AllDays.pptx`
  - `samples/output/sample-Mondays.pptx`
  - `samples/output/sample.xlsx`（新規）

### 段階5：仕上げ

- README.md を更新する。追加する内容は次のとおり。
  - 操作方法（ズーム、横スクロール）
  - Excel出力
- THIRD_PARTY_NOTICES.md
  - 依存関係に変更が無いことを、`dotnet list package --include-transitive` で確認する。
  - 変更があった場合だけ更新する。
- 最終確認として、次の3つを実行する。
  - `dotnet build -warnaserror`
  - `dotnet test`
  - publish（READMEに書かれたコマンドで実行し、出力先は `publish/` とする）
  - 加えて、`tools/Verify-Distribution.ps1` を実行する。
- publishしたexeを起動し、応答することと、正常に終了することを確認する。
